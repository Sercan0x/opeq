1Every wallet has the same lock

Every Solana account today is protected by one signature scheme, Ed25519. Its safety rests on one assumption: you can't work out a private key from its public key.

Shor's algorithm

In 1994 Peter Shor showed that a large enough quantum computer solves exactly that problem. Ed25519, secp256k1 and every elliptic curve in use today fall to it.

Your address is the key

On Solana the address is the public key. Every wallet that has ever received a token has already published everything a quantum attacker needs.

Migrations are slow

Nobody knows when such a machine arrives. Estimates range from five to twenty years. Moving a whole network to new signatures takes years too, so the work has to start before the threat is real.

Quantum computers do not break hash functions like SHA-256 in the same way. Grover's algorithm only halves the effective strength, which a long enough hash already absorbs. opeq builds its signatures from hashes alone.

2A wallet that stays safe

opeq is a Solana program plus a client. Your funds sit in an address that has no private key at all. The program moves them only after it checks a hash-based signature.

A normal address
Receive SOL, hold SPL and Token-2022 tokens, share it like any other address. Other programs see an ordinary signer.
Works with any app
One signature authorizes a list of instructions to any programs. Tested with transfers, tokens, token accounts, Memo and Raydium swaps.
Same address forever
One key tree signs 1008 transactions. A rekey moves to a fresh tree. Your address, balances and token accounts never change.
24 recovery words
Standard BIP39 words. Every key tree is derived from them, so the words stay valid after any number of rekeys.
No protocol change
Runs on Solana as it is today. No new chain, no fork, no waiting for a network upgrade.
Quantum-safe upgrades
The program's own upgrade key is an opeq wallet. Even the code can't be changed with a broken Ed25519 key.

3Ladders, a tree, a check

The signature scheme is WOTS+ (Winternitz one-time signatures) arranged in a Merkle tree, the same family as NIST's SLH-DSA standard. The diagram at the top of this page is a real signature, computed in your browser.

Eighteen ladders

Picture 18 ladders with 255 rungs each. At the bottom of every ladder sits a secret number. Climbing one rung means hashing the number once. Climbing is easy, coming down is impossible. The tops of all ladders together form the public key.

To sign, the message is hashed into 16 numbers from 0 to 255, plus 2 checksum numbers. For each ladder you reveal the rung the number points to. The verifier climbs the rest of the way and checks that every ladder reaches its top.

Why nobody can forge it

Someone who sees a signature can climb further up any ladder, so they could raise message numbers. The two checksum ladders stop that: if any message number goes up, the checksum must go down, and going down a ladder is impossible. The only way through is to find a different message with exactly the same 128-bit hash.

One tree, 1024 keys

A one-time key must never sign twice. So opeq makes 1024 of them and hashes their public keys pair by pair into a Merkle tree. The chain stores only the 16-byte root. Each signature carries its key's 160-byte path to the root. That is the opeq mark: the used key in blue, its path to the root filled, the unused keys empty.

On chain

  1. Your client signs. It reserves the next key and writes the counter to storage before signing, so a crash can never reuse a key. It hashes the exact instructions to run, then grinds a salt so verification is cheap.
  2. A normal transaction carries it. Phantom (or any Ed25519 key) pays the fee. That key only pays: it has no power over the opeq wallet.
  3. The program checks everything. Expiry slot, unused key, the hash of every inner instruction, all 18 ladders, the Merkle path, the root on chain.
  4. Then it acts. It advances the counter and calls the target programs, signing as your wallet address with invoke_signed.

The one rule: never reuse a key

Two different signatures from one key let an attacker forge a third. opeq is built around never letting that happen:

Counter first
The next key is reserved and saved before anything is signed. A crash just skips a key.
One tab at a time
A browser lock stops two tabs from signing with the same wallet at once.
Tamper check
The wallet record is authenticated with your password. Rolling back the counter or swapping the program address is detected.
Failed means burned
If a transaction fails, the client burns its key with a no-op so the failed signature can never run later.
Expiry
Every signature names a slot about a minute ahead. After it, the program rejects it.
Recovery skips ahead
Restoring from words reads the on-chain counter and skips 64 keys, in case a lost device signed something that never landed.

Internal reviews

7Built from scratch

The program is written in sBPF v3 assembly through a hand-made Python assembler. There is no Rust, LLVM or Solana CLI anywhere. A custom sBPF emulator runs the program locally with Solana's compute-unit prices. Its count matched the live network to within 0.05%. Every change is checked against a reference model with differential fuzzing.

This website is plain JavaScript with no dependencies: SHA-256, WOTS+, BIP39, base58, program addresses and the transaction format are all written by hand. It loads nothing from third parties.

9Questions

Is opeq live?

Not on mainnet yet. The program has not had an external audit. Please don't use it with real money yet.

When will quantum computers break Ed25519?

Nobody knows. Published estimates range from five to twenty years. What is certain is that network-wide migrations take years, and that on Solana every public key is already visible on chain.

Why not wait for Solana to add post-quantum signatures?

A Falcon verification syscall has been proposed (SIMD-0416), and a full migration plan exists on paper. Protocol migrations are slow. opeq works today, on the network as it is, and can adopt Falcon later.

Do I get a new address?

Yes. Your opeq wallet is a new address. You move funds into it like into any other address. After that the address never changes.

What does Phantom do here?

It pays transaction fees and approves them. Your funds don't live in Phantom: they live in the opeq address, which only moves with your hash-based signature. If Phantom's key were ever broken, the attacker would get the fee balance and nothing else.

Where are my keys stored?

In your browser, encrypted with your password (PBKDF2 with 600,000 rounds and AES-256-GCM). They never leave your device and are never sent to any server. The site loads nothing from third parties. An open wallet locks itself after 10 minutes without activity, and showing the 24 words always asks for the password again.

What if I clear my browser or lose my device?

Use your 24 words on the Recover screen. The client rebuilds your keys, finds your current tree on chain and skips ahead 64 keys to stay safe.

Can I use the same words on two devices?

For recovery, yes. Don't sign from two devices at the same time: each device tracks which keys it used, and two devices can't see each other's counters until a transaction lands.

What happens after 1008 transactions?

You rekey. The wallet moves to a fresh tree of 1024 keys derived from the same words. Your address, balances and words stay the same. The last 16 keys of every tree are reserved for this, so you can never get locked out.

How much does it cost?

The normal 5000 lamport fee. A transfer uses about 160,000 compute units, well inside Solana's limits. When priority fees apply, they scale with compute units, so a busy network costs a little more than a plain transfer.

Why are the signatures so big?

Hash-based signatures trade size for safety. 288 bytes of signature plus 160 bytes of Merkle path, 448 bytes in total, against 64 bytes for Ed25519. It still fits in one transaction, together with a swap.

Which apps work?

Any program that accepts a signer. Tested: system transfers, SPL Token, Token-2022, associated token accounts, Memo and Raydium CPMM. Large transactions need address lookup tables, which opeq supports. Programs that demand an Ed25519 signature from the wallet itself can't work with any program-based wallet.

Could the opeq team steal my funds?

The program can be upgraded, and whoever controls upgrades could change it. Today the upgrade key is itself an opeq wallet. Before mainnet the plan is to make the program immutable or put upgrades behind a multisig with a timelock, so users can leave before any change.

Is the code open source?

Yes, under the Apache 2.0 license. The repository goes public at launch.
